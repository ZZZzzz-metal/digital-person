# AI队：数字人综合情感陪伴对话模型技术方案

本次候选使用 Qwen2.5-0.5B-Instruct 完整本地基础权重，模型版本 `b2-a-qwen2.5-0.5b-instruct-base-v1`。核心目标是情感理解、多轮对话、记忆融合和共情表达的可运行原型。短训练实验已由 A 完成，但其候选权重尚未交到本次构建环境，不能把基础模型称作已微调提交版。

## 推理流程

官方调用 `bash /root/participant/start.sh TEST_FILE RESULT_DIR`。入口激活固定 `conda_env`，直接运行容器内 Python 适配器；不需要浏览器、HTTP服务、外部模型 API、登录或运行时下载。完整模型、tokenizer、配置、依赖和输出检查器随镜像提供。

输入逐行解析并按官方角色、轮次和目标预测点构造请求。输入 ID 原样回填；每个独立样本新建空 InMemoryStore，完整保留官方提供的历史，当前 user 只出现一次，不加入参考答案或产品演示库。模型进程仅初始化一次。容器将全部输入的结果写入 `submission.jsonl` 与 `performance_report.json`，独立检查器核对 ID、数量、四字段及有效 schema。

基础模型先尝试生成结构化 JSON；解析失败时，A 引擎使用真实模型文本回复，情绪与画像以规则补齐。此路径不返回固定回复或 mock。本次公开三条全部走该回退，意味着已证明执行链路可用，尚不能证明模型能稳定直接输出结构化字段或共情质量已达标。`memory_refs` 按公开要求使用空数组，不作为能力成绩。

## 产品记忆与官方隔离

演示后端支持匿名用户、会话历史和用户确认的记忆保存、相关话题检索、纠正、关闭及清空。SQLite持久存储以用户归属和事务隔离；当前轮去重和模型调用门控制重试。相关记忆作为候选上下文传给 A 引擎，不声称检索即模型必然引用。正式独立测评仅使用官方输入，不读取产品数据库或上一个样本状态。前端与产品演示不是官方测评的启动前提。

## 训练与优化方案

A 的已完成 CPU 小实验使用 200 条内部模板合成样本（150聊天格式、50官方输出格式），冻结前20层，只训练最后4层及最终norm，6次优化器更新。`official50` 是格式名称，不是真实官方标注。之后 A 独立整理真实官方训练200条、验证60条，按会话分离和目标时间截断，隔离顺序异常；该整理不代表已据此完成 GPU 训练。

平台 GPU 曾短暂完成 CUDA 矩阵运算，之后设备打开报 EPERM，未产生 GPU 训练权重。本次采用经过 B6 运行验证的基础模型；不将损失下降、CPU短回复速度或小案例结果当作正式能力提升。后续取得完整 SFT 权重和许可清单后，需另建候选、重新做同入口禁网验收，再决定是否替换。

## 适用范围与限制

应用定位为日常倾诉与校园生活陪伴原型，不提供诊断或治疗结论。模板训练规模小，仍可能误解话题、给出泛化建议、遗忘纠正或生成不恰当回应。项目尚无临床、商业用户或正式比赛成绩证据。隐私上默认匿名，长期记忆须用户确认且可删除；禁网测评只读官方数据，不混入真实用户私聊。后续质量优化由独立样本与实际反馈决定。

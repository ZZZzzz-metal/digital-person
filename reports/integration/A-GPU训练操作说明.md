# A 成员 GPU 训练操作说明

这份说明供负责 A 模型的同学使用。你只需要收文件、点击平台按钮、把页面交给原来的 A Agent；设备检查、训练和验证由 A Agent 完成，不需要手敲命令。这是 B 的协调交接说明，没有修改 A 的模型实现。

**页面依据：**下面的菜单名称和参考镜像来自 2026-10-10 已核对的咪咕平台页面，以及用户提供的原包 demo。2026-10-11 再访问创建页面时跳到了登录页，因此今天没有重新验证创建表单。按钮名称若不同，把当前页面交给 A Agent 核对。这份说明不代表已经为 A 创建新实例，也不代表 A 的 GPU 权限问题已经解决。

## 第 1 步：收 ZIP，解压到 D 盘的新文件夹

1. 在聊天里保存收到的数据 ZIP，保存位置选择 **D 盘**。
2. 打开文件所在位置，右键 ZIP，选择“全部解压缩”或解压软件中的“解压到指定文件夹”。
3. 在 D 盘新建一个独立文件夹，例如 `D:\A-GPU-20261011\数据`，选择这个文件夹后确认解压。不要覆盖 A 已有的代码、模型或数据文件夹。
4. 复制 ZIP 的完整路径和解压后文件夹路径，稍后发给 A Agent。若收到多个 ZIP，把每个路径都保留。

本次交接的原始 JSONL 文件分别有 **训练集 8,338 行对话、验证集 900 行对话**。这不是处理后预测点的数量。让 A Agent 从解压后的真实文件再次核对数量、字段和训练／验证划分，再按标注预测点整理训练输入，避免把标注答案或后续对话放进输入。数量或文件不一致时，先核对再训练。你不用逐条打开数据查看。

## 第 2 步：回到原来的 A 聊天，先确认代码和备份

打开之前负责 A 模型的那个聊天，把下面这段话复制进去：

> 我要继续 A 的 GPU 检查。请先确认代码提交 `727c92a` 已推送，并给我对应 PR 链接；再确认旧实例上的代码、模型、tokenizer、配置和训练日志已经备份，关机后仍能取得。请给出备份位置和取回方法，不能只留在正在运行的临时目录。ZIP 路径是：【粘贴路径】；解压目录是：【粘贴路径】。请先核对原始训练文件 8,338 行对话、验证文件 900 行对话，暂时不要启动训练。

收到明确的 PR 和可取回的备份位置后，再做下一步。提交号是待 A 确认的交接信息，这里没有替 A 宣称已推送、已合并或已完成备份。

## 第 3 步：关闭 A 自己的旧实例，保留文件

1. 打开[实例列表](https://aigpu.migu.cn/train/control/container/list)，按平台提示登录。
2. 只找 **A 自己之前使用的旧实例**。对照实例名称和 A Agent 给出的信息，不确定是哪台时，把列表页面交给 A Agent 指认。
3. 先确认第 2 步的备份能取回，再打开该实例的详情或操作菜单，选择“关机／停止”。
4. 等状态显示已关机或已停止。**保留实例，不点删除、释放或清空文件。**不要操作 B、其他队员或用途不明的实例。

## 第 4 步：创建一台新的 A GPU 检查实例

1. 打开[创建实例页面](https://aigpu.migu.cn/train/control/container/create)，或从实例列表点击“创建实例”。
2. 名称填写 **`a-gpu-check-1011`**。
3. 镜像选择“公有镜像”，找到 **“vLLM（大赛专用镜像-对话模型）”**。先前核对的参考版本为 **`vLLM:0.19.0-ubuntu22.04-p3.12-cuda12.8`**；按页面对应选项选择，不需要自己输入镜像地址。
4. 地区按页面可用资源选择，GPU 先选 **1 张 RTX 4090**。不要先选双卡；1 张卡的实际显存、软件版本和训练能否运行，后面由 A Agent 检查。
5. 打开平台的余额／卡券页面，确认 **GPU 卡券当前实际剩余卡时、支持的 GPU 型号和有效期**。不要直接沿用以前截图中的 20 卡时；卡券是否可用以现在页面为准。
6. 把镜像、GPU 规格和卡券余额页面交给 A Agent 核对。若只显示 CPU、没有 4090 可选、出现充值提示或卡券不能抵扣，先停在页面上让 A Agent 核对，不点充值，也不换成 CPU 当作 GPU 训练。
7. 核对可用余额和规格后，点击“创建／确认”。如果随后还有“开机／启动”按钮，再点击它。

这是参考开发环境，不是宣称该版本已通过 A 模型 GPU 验证，也不是把参考镜像规定为唯一可用版本。若菜单或版本变化，由 A Agent 根据当前页面确认后选择。

## 第 5 步：进入运行中的实例，把页面交给 A Agent

1. 回到实例列表，等待 `a-gpu-check-1011` 显示 **“运行中”**。
2. 点击该实例的“详情”。
3. 找到 **“Jupyter”** 或 **“控制台／终端”** 入口，点击进入。如果找不到，把详情页截图或当前浏览器页面交给 A Agent。
4. 在原 A 聊天发送实例名称、当前页面，以及第 1 步的 ZIP／解压目录路径。让 A Agent 将所需文件放入这台实例，并开始设备检查。

仅有“运行中”、看到显卡名称、或能打开 Jupyter，都不算模型 GPU 训练成功。不要自行粘贴网上的命令，也不要修改平台的设备权限或安全设置。

## 第 6 步：A Agent 检查通过后，再做一次受控短训练

把下面这段话复制给原 A Agent：

> 请在这台 A 专用新实例检查真实 GPU 设备及访问权限。只有 CUDA 矩阵运算实际成功、同步完成并保留日志后，才允许用不超过 200 条训练样本做小样本试跑，并验证模型保存后能够重新加载，再进行一次短训练。请保留原基线，别覆盖它。此轮累计预算不超过 6 GPU 卡时，同时不得超过当前实际可用余额和卡券有效期；开机检查、试跑和训练都计入预算。如果相同的 `/dev/nvidiactl` EPERM 权限错误再次出现，停止试跑，保存错误日志和已产生文件，确认备份能取回后关机，并把实例环境及错误证据交平台支持，不继续消耗卡时。

你不需要判断日志里的技术细节，让 A Agent 给出“设备权限检查结果、CUDA 同步结果、试跑结果、保存重载结果和实际卡时消耗”。这些结果必须来自实际运行，不能把计划或 CPU 运行写成 GPU 成功。

**预算按 GPU 卡时计算：**1 张卡运行 1 小时通常对应 1 GPU 卡时；若后来经核对改用 2 张卡，运行 1 小时通常对应 2 GPU 卡时。最终扣费和可抵扣范围以平台实际记录为准，因此“6 GPU 卡时”不等于任意规格都能开机 6 小时。余额不足时缩短或停止，不自动充值。

训练集与验证集保持分开。小样本试跑、一次短训练和保存重载是本轮操作范围，不要求你完成长时间搜索、多轮试验或赛事上传。

## 第 7 步：拿齐交接材料，备份后关机

让 A Agent 提供下面这些材料，再把链接或文件位置交给 B：

- **代码 PR：**对应提交、PR 链接、改动内容与实际验证结果；合并和拉取仍由你按团队约定处理。
- **大权重的取回位置：**平台存储或下载位置、取回方法、文件大小和逐文件 SHA-256。大权重不要只存在运行实例的临时目录，也不要直接塞进普通 Git 代码提交。
- **完整模型包：**权重、完整 tokenizer 文件、推理配置、所需模型配置和许可证；明确是原基线还是新训练版本，保留基线的取回位置。
- **真实运行依据：**实际依赖版本、GPU／CUDA 检查日志、小样本结果、短训练日志、保存后重新加载结果，以及实际使用的卡时。失败也保留原始日志，不能写成通过。
- **交接说明：**B 应使用哪个配置和模型目录、如何取回文件、已验证到哪一步、仍有哪些未解决问题。GPU 训练成功不等于 B 的 Docker 禁网镜像验收成功。

确认材料在关机后可取回，再回到实例列表，把这台 A 自己的新实例关机，**保留，不删除**。如果训练失败，同样先保存日志、备份文件再关机。这里不安排赛事提交、镜像上传或 B7 评测。

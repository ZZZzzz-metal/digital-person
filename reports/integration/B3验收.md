# B3 验收：记忆保存、检索、纠正和关闭

验收日期：2026-10-10（北京时间）；精确 UTC 时间见结构化记录。分支 `codex/b3-memory`，起点为已验证 B2 提交 `ac80f58`。启动时只读确认 PR #6 已合并，没有 fetch/pull/merge；复用 B1 已安装的独立环境。

## 已交付行为

SQLiteStore/InMemoryStore 新增用户级 memories 和五个存储方法，演示后端提供 GET memories、PUT settings、PUT key、DELETE id 和 DELETE 全部。五项 key 白名单、严格 DTO、值 trim 后 1–200 字符及 UTC 时间戳沿用 B1，未修改 schema 或 A/C 文件。随机 cookie 身份沿用 B2，客户端不能指定 user_id/id/timestamp。

只有用户明确保存才写入，未实现自动候选落库或情绪/诊断事实推断。同用户同 key 纠正原地更新，保留 id；旧值不会和新值一起进入检索。记忆跨会话可用，删除会话保留事实。陌生用户的 id 和不存在 id 统一 404。

关闭后读取返回 false/[]，不查询事实值；保存 409 MEMORY_DISABLED 且不改旧值。重新开启恢复保留事实。用户明确删除/清空在关闭时仍可操作，清空不改变开关，只影响当前用户。

`src/b2_core/memory.py` 的 build_memory_context 为纯函数，匹配字段话题或有意义的具体值，最多五项；同 key 的重复候选只保留最新事实，返回独立 DTO。无关或关闭时文本为空。值按 JSON 用户事实包装，不升格为系统指令；包装不能保证实际模型完全抵抗提示注入。候选列表不证明模型已经引用。

## 运行方法与交接

按根 README 启动当前演示：

```powershell
$env:B2_MODE = "stub"
.\.venv\Scripts\python.exe -m uvicorn server.app:app --host 127.0.0.1 --port 8000
```

保留匿名 cookie 后调用五个记忆接口；README 有高数→线代→关闭→开启→删除/清空的 PowerShell 操作。独立复现本轮验收：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/server -q
.\.venv\Scripts\python.exe reports/integration/verify_b3_http.py --port 0
```

HTTP 脚本自己启动/关闭服务，使用空闲端口与独立 DB，不需要预先启动后端。B1/B2 的报告保留为当时记录，旧 HTTP 脚本检查历史路由快照；当前版本运行 B3 脚本。

A/C 通过本 PR 的总约定第 8 节和 contracts/README 同步，不改变 DTO 字段；C 可对接记忆管理及 MEMORY_DISABLED，A 后续接收 memory_context。用户手动合并、拉取。本轮无人工技术阻塞，完成上传后停止等 B4 指令。

本轮未实现 `/api/chat`，未验收真实模型生成、训练、正式离线适配、禁网容器、参赛回退候选或平台提交。这些是后续阶段工作，不能用本次记忆测试代替。实际提交和 PR 见 [B 进度记录](B-进度记录.md)。

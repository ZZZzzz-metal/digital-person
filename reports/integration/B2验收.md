# B2 验收：匿名用户、存储与会话接口

验收日期：2026-10-10（北京时间）；精确 UTC 时间保存在结构化报告。分支 `codex/b2-storage-sessions`，起点为已验证 B1 的 `c85e971`。B1 的 PR #5 已只读确认合并；本轮没有 fetch/pull/merge，也没有再次获取已核对的官方资料。

## 交付范围

`src/b2_core/store.py` 提供 SQLiteStore、每实例独立 SQLite 内存数据库的 InMemoryStore，以及共用的 Store 协议。包含匿名身份映射、users/sessions/messages/turns 表、归属检查、原子完成、成功重试缓存、同会话占用及过期恢复。

`src/server/app.py` 和 `sessions.py` 提供四个会话操作：创建、列表、消息历史、删除。成功 JSON 使用 B1 既有 DTO/schema，不改变 A/C 字段；400/404/409 统一 error 对象，OpenAPI 不再把参数错误写成默认 422。健康接口保留原 mock/real 语义，不分配 cookie。

首次 API 访问生成不透明 cookie token，SQLite 只存 SHA-256 和独立 user_id；用户不可通过 body/query 或伪造 cookie 指定另一个人的身份。cookie 为 HttpOnly、SameSite=Lax、Path=/，本机 Secure=false，HTTPS 可设置 B2_COOKIE_SECURE=1。默认数据库 `.runtime/b2.sqlite3` 被 Git 忽略；应用只关闭自建 store，注入 store 仍由调用者管理。

本轮没有实现 `/api/chat`、产品长期记忆或模型历史编排。turn 去重/失败验证直接使用存储与明确的测试 fixture，不声称真实模型生成通过。共享内部方法与删除 pending 时的 409 策略已经先同步总约定。

## 实际验证

| 检查 | 实际结果 | 证据 |
|---|---|---|
| 回归与新功能 | **123 passed**，0 failures/errors/skipped；包含 44 合同、20 健康、28 会话 API、31 存储用例 | [结构化验收](b2-verification.json)，`tests/server/` |
| 两用户隔离 | 两个 cookie 用户独立创建/list/read/delete；不属当前用户与不存在统一 404；伪造 token/user_id 不能访问旧用户 | 同上 |
| 去重/并发 | 已完成的同 turn 返回原 response，只一对消息；同文本不同 turn 两对消息；同会话 pending 冲突；两个 SQLiteStore 同时竞争仅一个成功 | 同上 |
| 失败原子性 | 测试主动在第二条 assistant INSERT 用 SQLite trigger 抛错，前条 user 也回滚，turn 保持 pending；去掉 trigger 后同 reservation 可正常完成 | 同上 |
| 过期/删除/副本 | 旧 token 不能提交或释放新 pending；有效 pending 删除 409；完成/过期后可删除并级联 messages/turns；修改返回 DTO 不改存储 | 同上 |
| schema/依赖 | 21 schemas/21 虚构 examples 一致；pip check 无冲突；沿用 B1 环境，无新增依赖/锁变动 | 同上 |
| 实际 HTTP 和重启 | **8 项检查通过**，两个独立 Uvicorn 进程：健康无 cookie、两身份隔离、400、读取 fixture 消息、五个 HTTP 操作、重启保留原 cookie 会话和消息、归属删除 | [HTTP 实测](b2-http-smoke.json) |

HTTP 检查使用隔离临时 SQLite 文件，消息来自注明“B2虚构fixture”的存储写入，没有调用 engine，也没有实现聊天路由。两个进程都由检查脚本创建并已停止，未关闭其他服务；原始 cookie 不写入报告/日志。

本轮在 B1 已验证的 Windows Python 3.12.14 环境运行。pytest 用时显示 2.44 秒，不是模型推理性能。有一条原有 Starlette TestClient 弃用提示，以及两条故意把 mock 布尔字段改成整数的负例序列化提示；两个错误值都被严格重新校验拒绝，警告未隐藏。

## 运行与继续位置

按根 [README](../../README.md) 安装并启动，或在端口空闲时执行：

```powershell
.\.venv\Scripts\python.exe reports/integration/verify_b2_http.py --port 8000
```

端口被占用时用 `--port 0`，不关闭已有服务。浏览器/客户端必须保留服务端 cookie，再调用会话 API；README 有可直接复制的 PowerShell 顺序操作。创建的新会话尚无聊天输入入口，历史初始为 `[]`。

本轮没有人工技术阻塞。上传 PR 后由用户手动合并、拉取；B2 完成就停止。下一步 B3 实现用户主动确认的记忆保存/检索/纠正/关闭，之后 B4 才接聊天模型流程。真实模型、训练、正式适配、禁网容器、参赛回退候选和平台提交仍须后续实际验收。

精确提交与 PR 链接持续更新在 [B 进度记录](B-进度记录.md)。

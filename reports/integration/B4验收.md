## 已交付的行为

POST `/api/chat` 先校验会话归属并占用轮次，取已完成历史和相关记忆，再调用 A 的 engine；成功后在一个事务内保存用户/assistant/turn 结果。失败、超时或取消不保存半轮。相同成功 turn ID 原样返回缓存，不再调用模型；相同文本的新 ID 是新请求。

纯 `build_core_request` 从最近最多 12 条历史删除最旧完整轮次直到历史不超过 4,000 字符，当前不超过 2,000 字符的输入只追加一次且不截断；A 继续负责 tokenizer 的长度。纯 `run_turn` 校验后调用 generate 一次，不加载模型、不读数据库、不需要 HTTP/cookie/浏览器。演示 CoreRequest 与官方 OfficialRequest 不同，不能直接拿它当完整官方适配器。

模型元数据须真实一致。损坏情绪/表情归为 unknown/neutral；空白回复、错误类型或 is_mock/版本不符都失败。真实模式加载失败永不退到 stub。模型自身抛出的 ChatError/TimeoutError 也统一为 MODEL_UNAVAILABLE，不透传输入或原始异常。

| 状态 | HTTP / code | 客户端处理 |
|---|---|---|
| 参数不符合合同 | 400 INVALID_REQUEST | 修正输入 |
| 会话不存在/属于别人 | 404 NOT_FOUND | 保留输入，选择自己的会话 |
| 同会话正在生成 | 409 TURN_IN_PROGRESS | 保留原输入和原 turn ID，稍后重试 |
| 全局 engine 仍在计算 | 503 MODEL_BUSY | 同上 |
| HTTP 等待超时 | 503 MODEL_TIMEOUT | 同上 |
| 模型缺失/异常/输出损坏 | 503 MODEL_UNAVAILABLE | 修复模型环境后，用原 turn ID 重试 |

演示等待默认 60 秒，`B2_CHAT_TIMEOUT_SECONDS` 允许 `(0,240]`，低于存储默认租期 300 秒。这些是内部策略，不是官方约束。Python 线程不能强杀：HTTP 超时释放 turn，占用 engine 的 gate 保持到实际计算结束，迟到结果丢弃；同应用重新开 lifespan 也不提前释放。永久卡住需要重启该后端进程。数据库短事务同步执行，未持有事务等待推理。

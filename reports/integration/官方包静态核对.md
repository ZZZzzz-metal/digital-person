# 官方包静态核对记录

日期：2026-10-09。输入为队伍提供的《数字人综合情感陪伴对话模型.zip》。这是源码、格式和数据检查记录；没有执行官方推理、训练、依赖安装、Docker 构建或平台测评。

## 本次实际执行的检查

- 原 ZIP 可解压且 CRC 检查通过；27,076,587 字节，21 个条目（含目录），展开文件总大小 79,923,605 字节。
- 12 个发布的原始小文件/副本与本地源逐字节相同，共 44,968 字节。来源、去向及 SHA256 记录在 [source-manifest.json](../../contracts/official/source-manifest.json)。原始大数据与 DOCX 留本地，不进 Git。
- 两个 B 目录内的 .gitattributes 禁止原始快照换行转换；在本机 core.autocrlf=true 下检查 Git 暂存字节和模拟检出字节，12 份副本均保持原始 SHA256。
- JSON 文件可解析；官方 run_inference.py 通过 Python AST 语法读取，未执行其 main，也未据此声称依赖或模型可用。
- 自写只读 [inspect_official_dataset.py](inspect_official_dataset.py) 在完整 train、val 和小推理输入上实际运行；结果为 [dataset-audit.json](dataset-audit.json)。报告不包含聊天文本和本机账号路径。
- 当前 Python 没有 jsonschema 包；检查器覆盖实际两份数据 schema 中出现的全部验证关键词（含本地 $ref、枚举、正则、唯一数组、额外字段限制），报告记录 unsupported_schema_keywords=[]。这不是通用 Draft 2020-12 验证器，也不是官方评分器。

四个训练预测点引用目标 user 之前的 assistant，结构合法但不适合直接作为下一轮回复监督：

|---|---:|---:|
| train_conv_000628 | 15 | 14 |
| train_conv_000817 | 33 | 32 |
| train_conv_003644 | 7 | 6 |

A 在自己的数据处理区域先隔离这些点，不改官方原始数据，不猜测目标回复。所有引用 turn 均存在、角色正确，target.response_text 与被引用 assistant 文本一致；异常是时间顺序，并非 JSON 解析错误。

小推理样例 3 行、3 个唯一 id、2 个 conversation_id，history 长度 5/5/7，全部最后为目标 user。没有 target/参考答案，没有 memory bank。三个输入 id 均不符合输出 schema 的 test_ 正则；该矛盾与默认 100 轮只给 3 条输入的问题已记录在 [官方接口核对](../../docs/官方接口核对.md)。没有实际生成 submission 或 performance report。

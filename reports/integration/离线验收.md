## 镜像与实际运行方法

Linux 镜像固定入口为 `bash /root/participant/start.sh TEST_FILE RESULT_DIR`，自动激活 `conda_env`。整个包复制到 `/root/participant`，通过 `B2_OFFICIAL_MODEL_CONFIG` 使用原基线配置；不需要启动浏览器、HTTP 服务、输入账号或调用外部模型 API。

构建候选基于 `pytorch/pytorch:2.8.0-cuda12.8-cudnn9-runtime` 的已读取 linux/amd64 digest：`sha256:417bd75df6365104c283ea4c1651fb3530d9eb5a4c2fafa51943cff2a94e6385`。来源证据见 [base-source.json](../../deploy/base-source.json)。该镜像尚未拉取/构建；公开元数据的压缩层大小不代表最终镜像大小。

`requirements-gpu.txt` 固定四个直接依赖版本，Torch 来自上述候选基础镜像。它是待实测配方，**不是已验证 GPU 环境完整锁**。构建成功后会保存实际 pip freeze、conda explicit 和 pip check；运行探针再保存同镜像依赖、CUDA 内核与包清单核对结果。

在具备 Linux Docker 和 NVIDIA GPU 支持的主机，把 D 盘完整包复制至新本地目录后，从合并后的项目根目录运行：

```bash
python deploy/prepare_bundle.py verify /data/b2/candidate-a34f8df
python deploy/verify_container.py \
  --bundle /data/b2/candidate-a34f8df \
  --test-file submission/official-reference/test_inference_data.jsonl \
  --work /data/b2/b6-docker-new-run
```

`--work` 必须不存在；输入须是 JSONL。构建期需要下载依赖，运行期全部 `--network none`。自动工具使用同一不可变 image ID 做 GPU 探针、实际模型推理、独立结果检查和 Docker save；只清理自己创建的容器。GPU 探针成功之外，还要求实际推理日志明确为 CUDA，防止模型悄悄在 CPU 上运行。

成功时 `verification.json` 必须同时有 `gpu_offline_verified=true`、`fallback_image_verified=true`，并保存 `fallback-image.tar`、其 SHA、实际 image ID、网络/GPU inspect、依赖、时长及两个结果文件。结果挂载目录必须支持入口使用的硬链接发布。团队预算为镜像 inspect Size 和导出 tar 均小于 50,000,000,000 字节；这是内部留余量策略，官方只答复“50G以内”。

公开三条全部输出时，参考计时仍为 `complete=false`；需完整输出/ID 顺序一致，而非伪造 100 条计时。校验成功也不代表模型质量或官方得分已通过。

## 实际尝试与权限阻塞

自建实例 `b6-offline-test-1011` 使用平台公有 `vLLM:0.19.0-ubuntu22.04-p3.12-cuda12.8`。实测两卡 CUDA 计算成功，`unshare -n true` 返回 0；后者仅证明网络 namespace 能力，不能代替 Docker 容器启动或模型验收。

只在 `/root/b2-b6-20261011` 安装官方静态 Docker 并启动自有 Unix socket 服务。Docker Hub 请求实际失败；随后从平台 Bash 与它的动态库导入微型能力镜像，排除了下载失败这个前置因素。执行 `docker run --network none` 仍退出 125，核心错误：

```text
unable to apply cgroup configuration:
mkdir /sys/fs/cgroup/cpuset/docker: read-only file system
```

该能力镜像不含 B2 模型，其 ID 只在能力报告中记录，不能填为正式候选 image ID。未修改平台宿主机权限或关闭安全限制。

独立 runc 能力尝试退出 1：第一次 session keyring 无权限；加官方单次 `--no-new-keyring` 参数后，仍因 `/proc` 挂载 `operation not permitted` 失败。该 rootless 默认配置未请求独立 network namespace，因此即使启动成功也不能记为网络隔离验收；此次没有成功启动。不把 runc 尝试替换为 Docker 验收通过，不继续绕过挂载安全限制。

首次收尾时本机 Docker CLI 不存在、WSL 未安装；当时进程不是管理员，只做了只读系统核对。之后用户授权自行安装，已实际装好 WSL3.0.1 并启用 VMP，需Windows重启生效，最新记录见 [本机环境续做](B6-本机环境续做.md)。Hypervisor/CIM 的原始观察不等于 WSL 可用。Windows GPU Docker 的官方准备说明见 [Docker GPU 支持](https://docs.docker.com/desktop/features/gpu/)。

已请求停止自己启动的 Docker 服务并关机测试实例；平台最终显示 **已关机、总卡时余额 29.23**（包含不同种类券，不能说成剩余 GPU 卡时）。最初总量 30，显示差额 0.77；页面数值为本次观察，不是永久余额。小截图保留于本机 `.b6-work/platform-stopped-final.png`，未公开账号截图。

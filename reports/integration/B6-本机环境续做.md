## 重启后继续

Windows 返回3010表示需要重启；当前 `wsl --status` 仍提示 WSL2 的虚拟化组件尚不可用。先让这次组件安装重启生效，再核对，不凭重启前的提示断言 BIOS 必须修改。[微软安装说明](https://learn.microsoft.com/en-us/windows/wsl/install#offline-install)

用户保存工作并手动重启后，Agent 从此处继续。不会重新下载已经校验的安装包或模型；从项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -B deploy/resume_b6_local.py --verify
```

该续做工具会：核对原安装文件；只注册 `B2-B6-Ubuntu22` 到 `D:/B2-B6-20261011/setup/wsl/B2-B6-Ubuntu22`；真实启动 Linux；执行专用环境脚本安装官方 Docker Engine 与 NVIDIA Container Toolkit；再调用原 B6 工具构建并在禁网 GPU 容器内运行全量公开输入、独立校验与导出同镜像回退。新日志放 D，完整验收目录位于发行版的 `/root/b2-b6/runs`，物理磁盘仍是 D 上的 VHDX。

运行前仍要核对实际专用发行版名/磁盘路径。已有同名但其他路径的发行版、非空未知目标、错误宿主或安装文件摘要改变都会失败，不能覆盖。Docker/Containerd 保持 Linux ext4 默认数据目录，全部在 D 上的发行版磁盘，不把 overlay 数据根设在 `/mnt/d`。交换盘位置遵循 [微软 WSL 配置](https://learn.microsoft.com/en-us/windows/wsl/wsl-config)。

Linux安装和验收分别设限时并先发送INT，Windows客户端多留清理时间；超时保存该步骤已有输出与失败状态。容器验证异常时限时停止、强制移除本次创建的CID并记录cleanup证据，清理失败不会返回成功。实际33项容器控制检查通过，其中3项新增取消/清理测试；这些使用模拟Docker数据，不代表真实镜像或GPU验收。

不安装 Docker Desktop；专用 WSL 中使用 [Docker 官方签名 apt 源](https://docs.docker.com/engine/install/ubuntu/)与 [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)。WSL 使用已安装 Windows 驱动，**不安装 Linux 显卡驱动或 cuda-drivers 元包**。[NVIDIA WSL 说明](https://docs.nvidia.com/cuda/wsl-user-guide/index.html)

## 3. 接口

```python
from pathlib import Path
from b2_core.model import create_engine

engine = create_engine("weights/inference_config.json", mode="real")

# ① 演示合同
reply = engine.generate(core_request)                 # -> CoreReply
reply.reply, reply.emotion, reply.expression, reply.is_mock, reply.model_version

# ② 官方合同（B 的最新约定）
prediction = engine.generate_official(official_request)   # -> OfficialPrediction
#   prediction.response_text / emotion_label / user_profile / memory_refs
```

- `mode="mock"` 得到 `MockEngine`（`is_mock=True`、`model_version="mock-v1"`），
  不加载任何权重，用于前端联调。
- 诊断用：`generate_with_trace(...)`、`official_trace(...)` 返回中间量
  （prompt tokens、是否裁剪历史、JSON 还是回退、耗时）。
- 异常：`ModelUnavailableError`（权重缺失/目录不完整）、`InvalidRequestError`（请求不合法）。
  两者都**不会静默退回 mock**。

### 合同绑定方式（重要）

`src/b2_core/a_impl/dtos.py` 会**优先使用 B 落地的 `b2_core.contracts`**；
如果那里还没有对应的类，就用 A 的兜底 dataclass。
`engine.describe()["contract_source"]` 与 trace 里的 `contract_source` 会写明当前用的是哪一套。

> 也就是说：**B 把真实合同类放进去之后，A 的引擎会自动用 B 的类，A 不需要改代码。**
> 目前仓库里没有 `src/b2_core/contracts.py`，所以现在走的是 A 的兜底合同。

**这条已经实测过，不是口头承诺。** 用 [smoke_contract_binding.py](../../tests/model/smoke_contract_binding.py)
在内存里伪造一个 `b2_core.contracts`（不会在仓库里创建这个文件），验证了五种情况：
没有合同时用兜底、合同齐全时**整体**切到 B 的类型（含嵌套 `user_profile`）、
合同缺字段时**整体**退回（不出现一半 B 一半 A）、合同属性访问抛异常时安全退回、
以及**真实引擎 + B 的合同**两个接口都能跑通。结果见 [a5_contract_binding.json](a5_contract_binding.json)。

切换发生在**引擎构造时**（`ModelEngine.__init__` 调 `resolve_contracts()`），
所以 B 落地合同后需要**重新构造引擎**才会生效。

> 顺带修掉一个真实缺陷：`resolve_contracts()` 原来只把 `import` 包了 try，
> 属性检查若抛异常会漏给调用方；现在整段都有防护，任何异常都退回兜底。

## 6. 官方合同相关的硬约束（A 已按此实现）

- 16 类情绪：`joy, gratitude, relaxed, care, pride, neutral, surprise, mixed, sadness,
  loneliness, anxiety, anger, fear, disgust, shame, helplessness`。
- 三组画像：`personality_traits`(10) / `interests`(12) / `style`(11)，取值全在官方枚举内且不重复。
- **公开测试 `memory_refs` 强制为 `[]`**——没有公开 memory bank，不许编造引用。
  真实 memory bank 的查询与回填由 **B 侧**负责，A 只保证字段合法。
- 输出**只有四个字段**，没有 `id`、没有 `is_mock`、没有表情和耗时（这些由 B 回填）。
- 输入历史**原样使用**：不追加当前问题、不追加上一轮预测、不读标签。
- 缺权重时**报错**，绝不产出假预测。

## 7. 已知限制与风险（请务必一起看）

1. **本机没有 GPU。** `torch.cuda.is_available() == False`，无 `nvidia-smi`。
   所以 A4 **消耗 0 GPU 卡时**，是 CPU 上跑的小规模适配。
   20 卡时券对应的实例**仍需队长在咪咕仝学平台创建并提供访问权限**，
   A 无法自行登录，这是当前唯一的硬阻塞。
2. **候选模型只在 3 条公开样本中的 1 条直接输出合法 JSON**，
   其余走「解析失败 → 取纯文本 + 规则补标签」的回退。
   回退时 `response_text` 仍来自真实模型，情绪与画像来自规则。
3. **候选模型在长上下文里曾有复读退化**，已用 `repetition_penalty 1.15` 消除；
   若 B 改成更低的值，退化会回来。四个配置的实测见 A5。
4. **训练规模极小**：200 条合成样本、最后 4 层、6 次 optimizer step、约 7.2 分钟。
   它证明了链路可跑通、能保存、能重载、能评测，**不代表能力有明显提升**。
5. **没有跑过官方 `start.sh`**，因此没有 `submission.jsonl` / `performance_report.json` 的真实成绩。
   正式提交入口在 B 侧；A 只保证引擎侧合同正确。
6. 训练数据是**模板化自动生成的虚构对话**，情绪与画像标签由规则标注，
   不是人工标注、也不是官方标签。见 [A2](A2-数据来源与许可清单.md)。
7. **A 只在 1 台机器、1 个解释器上验证过**；换环境需要重新跑第 1 节的自测命令。

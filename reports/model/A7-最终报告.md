## 3. 阻塞与未完成项（不粉饰）

### 🔴 阻塞 1：本机没有 GPU，20 卡时券用不了

- `torch.cuda.is_available() == False`，`device_count == 0`，无 `nvidia-smi`，无 NVIDIA/CUDA 目录。
- A4 要求「最多 6 GPU 卡时」，实际**消耗 0 卡时**——这是环境限制，不是省着用。
- 咪咕仝学平台的 20 卡时券**需要人工登录才能创建实例**，A 无法自行完成。
  券页面显示 **10/16 23:17:54 到期**，而交接目标是 10/15。
- **需要队长/人工**：在平台上创建实例并把访问方式给 A，A 才能按 6 卡时上限重跑一次真正的 GPU 训练。
- 在此之前，交付的候选模型是**CPU 上跑的缩小版适配**（只训最后 4 层）。

### 🟡 限制 2：权重不在 Git 里

`weights/base-qwen2.5-0.5b-instruct/`（953 MB）与 `weights/sft-short/`（1.9 GB）按 `.gitignore` 排除。
**clone 仓库不会得到权重。** B/C 需要真实引擎时必须另外拷贝实体文件，
并用 [weights/MANIFEST.json](../../weights/MANIFEST.json) 校验 sha256。

### 🟡 限制 3：没有官方成绩

A **没有跑过官方 `start.sh`**，因此没有 `submission.jsonl`，也没有 `performance_report.json`。
所有评测都是 A 自建的 12 案例 + 公开的 3 条推理输入，**不等同官方评分**。
正式提交入口在 B 侧。

### 🟡 限制 4：候选模型的 JSON 遵循率只有 1/3

3 条公开样本里只有 1 条直接产出合法 JSON，另外 2 条走「解析失败 → 取纯文本 + 规则补标签」的回退。
回退时 `response_text` **仍来自真实模型**，情绪与画像来自规则。
这是 0.5B 模型 + 6 步训练的真实水平。

### 🟡 限制 5：训练规模极小

200 条模板化合成样本、6 次 optimizer step。它证明了链路可跑通、能保存、能重载、能评测，
**不能证明能力有实质提升**。合成数据的问答相关性也有限（见 [A2](A2-数据来源与许可清单.md)）。

### 🟡 限制 6：候选模型有可观察的常识错误

例如把"室友"说成"房东"。这是 0.5B 模型的常见失败，未做掩盖，样例原样保留在 [A1](A1-真实引擎记录.md)。

### 🟡 限制 7：仓库没有根 `.gitignore`

A 之前误提交过 9 个 `.pyc`，已从索引移除；现在只在 A 自己的目录（`src/b2_core/a_impl/`、
`src/b2_core/prompts/`、`tests/model/`、`data/`、`training/`）各放了 `.gitignore`。
**A 没有创建根 `.gitignore`，因为那是共享文件。**
建议 B 在根 `.gitignore` 加上 `__pycache__/` 与 `*.pyc`。

**A 无法完成推送，原因是本机环境，不是仓库问题：**

   `Failed to connect to github.com port 443 after 21111 ms: Could not connect to server`，

   本机的 GitHub 连通性是**间歇性**的——最初的 clone 成功了，之后就一直连不上。

   仓库是 `ZZZzzz-metal/digital-person`，push 需要该账号的凭据（token 或 SSH key），
   A 没有，也不应该去索取。
3. 受限沙箱下 git 还会因信号管道被拒而失败（`couldn't create signal pipe, Win32 error 5`），
   这一条**在放宽权限后已不再出现**，剩下的是上面 1、2 两条。

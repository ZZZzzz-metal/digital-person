## 4. 当前卡住的根本原因：容器没有分到 GPU

### 4.1 结论

**GPU 不可用不是代码或环境问题，而是平台侧没有把 GPU 分配给这个 pod。**
容器内无法修复，必须重建实例或找平台支持。

### 4.2 报错证据（全部为实测）

| 检查项 | 结果 |
| --- | --- |
| 宿主机 `/proc/driver/nvidia/gpus/*/information` | 4 张 **RTX 4090**，驱动 **595.71.05**，全部正常 |
| 容器 `ls /dev/nvidia*` | `nvidia0/2/6/7`、`nvidiactl`、`nvidia-uvm`、`nvidia-uvm-tools` **存在** |
| **以 root 打开 `/dev/nvidiactl`** | **`PermissionError [Errno 1] Operation not permitted`** |
| 同样打开 `/dev/nvidia0`、`/dev/nvidia-uvm` | 同样 `Operation not permitted` |
| `/dev/nvidia-caps/` | **不存在**（`/proc/devices` 显示正确主设备号是 `235 nvidia-caps`） |
| `NVIDIA_VISIBLE_DEVICES` / `CUDA_VISIBLE_DEVICES` | **均未设置**（`env \| grep -i nvidia` 无输出） |
| `/dev/nvidia*` 时间戳 | **2026-09-09 15:20**（镜像构建时间，非容器启动时间 10-11 02:53） |
| `nvidia-smi` | `Failed to initialize NVML: Unknown Error` |
| torch | `torch 2.10.0+cu128`，`cuda_available False`，`device_count 0` |
| `torch.cuda.init()` | `RuntimeError: No CUDA GPUs are available` |
| 容器编排 | k8s pod：`kubepods.slice/kubepods-burstable.slice/kubepods-burstable-podf2904416_d7ca_4f8a_a024_24546107f108.slice/cri-containerd-c4615dbff7fd…scope` |
| `dmesg` | 不可用（容器内无输出） |

### 4.3 诊断推理

容器被分到 GPU 时，运行时（nvidia-container-runtime + device plugin）应当：

1. 注入设备节点并**放行 device cgroup**
2. 创建 `/dev/nvidia-caps/nvidia-cap*`
3. 设置 `NVIDIA_VISIBLE_DEVICES`

**这三件事一件都没发生。** 而 `/dev/nvidia*` 节点存在、时间戳是镜像构建日，
说明它们只是**打包在镜像里的摆设**，真正决定可用性的是 device cgroup——它拒绝了 root 的 `open()`。

**可能原因（按可能性排序，无法从容器内区分）：**

1. 创建实例时没真正选中「显卡型号 + 卡数」资源项（只选了镜像）
2. 所选机房单卡库存为 0，平台降级成 CPU-only 实例
3. 调度给了 GPU 节点但 device plugin 未分配（平台 bug）

### 4.4 给平台支持的话术

> 实例 `b2-a-train`（pod `f2904416-d7ca-4f8a-a024-24546107f108`，容器 `c4615dbff7fd`）里
> `/dev/nvidia0` 等节点存在，但 root 打开报 `Operation not permitted`，`/dev/nvidia-caps` 缺失，
> `NVIDIA_VISIBLE_DEVICES` 未设置，`nvidia-smi` 报 `Failed to initialize NVML: Unknown Error`，
> torch `cuda_available=False`。宿主驱动 595.71.05 正常。请检查该 pod 是否被分配了
> GPU 设备与 device cgroup 权限。

## 自动入口与输出

来源：`participant/README.md:83–105`、`participant/start.sh:1–50,95–149`。

```bash
bash /root/participant/start.sh TEST_FILE RESULT_DIR
```

- 参数一是具体 `.jsonl` 文件，不是输入目录；参数二是结果目录。
- 官方说明固定 `/root/participant/start.sh` 路径和两个位置参数，主办方只调用此入口。
- 脚本最先 `source activate conda_env`；注释要求该环境名固定。实际平台镜像是否已带此环境，尚未验证。
- 全量输入生成 `RESULT_DIR/submission.jsonl` 和 `RESULT_DIR/performance_report.json`。不要求浏览器、演示 FastAPI 或 SQLite 已启动。
- 结果目录可已有其他文件，参考脚本只写上述两个名字；验收仍应使用新目录，避免失败后混用旧报告。

根 README 另要求将技术方案、实验报告、平台训练/调优记录放入提交镜像 `/root` 下，目录命名为 `AI技术赛道-数字人综合情感对话模型-队名`。这是资料放置要求，不是已核实的镜像文件名、上传地址或评分公式。

## 输入和历史边界

来源：`run_inference.py:57–74,228–234,410–412`；原样小输入见 [test_inference_data.jsonl](../submission/official-reference/test_inference_data.jsonl)。

小输入每行包含 `id`、`conversation_id`、`target_user_turn_id`、`history`。history 项含 turn_id、role、content，最后一项是目标 user。代码入口仅要求 id 为字符串、history 为数组，随后检查每条 role 为 user/assistant、content 为字符串；测试文件非空且样本 id 不重复。原包未提供专用测试输入 schema，不能把 train schema 用来验证这种输入。

参考脚本只读取 id/history，把完整历史渲染进一条模型 user 消息；不另追加当前问题，不读取标签/答案，不累积上一条预测。即使两个样本有相同 conversation_id，也各自使用已给定的完整历史。B 保持输入顺序及 id 原值，不用 conversation_id 代替样本 id。

## 输出和模型生成合同

来源：`participant/templates/submission_schema.json:4–20`、`run_inference.py:33–47,271–315`。

每行只允许以下五个字段，其他字段禁止：

| 字段 | 含义与限制 |
|---|---|
| id | 从对应输入原样回填；新答复已明确，旧包前缀正则不作为当前拒绝依据 |
| response_text | 中文回复；官方 schema 仅要求字符串，prompt 要求非空 |
| emotion_label | 最新 user 的 16 类情绪之一；schema 另允许失败占位 `""` |
| user_profile | 必须有 personality_traits、interests、style 三组枚举数组；无证据可为空 |
| memory_refs | 原快照规定不重复的 mem_XXXXXX 字符串数组；新答复明确不评分，团队默认 `[]` |

16 类为 `joy, gratitude, relaxed, care, pride, neutral, surprise, mixed, sadness, loneliness, anxiety, anger, fear, disgust, shame, helplessness`。完整画像枚举见 [官方输出 schema](../contracts/official/submission.schema.json)。

A 生成的是后四个字段，B 回填 id。原内部 CoreReply 的六类情绪和表情只能用于演示；必须保留独立官方输出，不能从六类反推 16 类或遗漏画像。团队派生的 [model_prediction.schema.json](../contracts/official/model_prediction.schema.json) 排除 id 和失败空值，供 A 约束成功生成，已标明不是官方原文件。

训练/验证 target 中有非空 memory_refs，但没有对应 memory bank 或记忆内容映射。原 system prompt 因测试没有公开 memory bank 而要求 `[]`；2026-10-10 新答复明确 memory_refs 不参与评分，并写“无限制”。团队仍选择 `[]`，不把该选择写成官方评分强制空数组。mem 数字不能当 turn_id，演示数据库 ID 不能混入。新答复没有说明是否将提供 memory bank；其余输出结构约束保留。

按新答复新增 [effective_submission.schema.json](../contracts/official/effective_submission.schema.json)：它是团队由原始快照派生的有效合同，只删除 `id.pattern` 并注明来源，保留其他约束。原始 [submission.schema.json](../contracts/official/submission.schema.json) 字节不变。输出 ID 必须逐项与输入完全相等，不能仅凭通过 schema 判定对齐；本轮仅验证合同，不修改 B5 适配器。

## 性能报告和失败行为

来源：`run_inference.py:397–461`。

全量推理，但只取前 performance_rounds 条计时，默认 100；新答复确认只统计前 100 条数据耗时，不是只生成前 100 条。Transformers 计时包括 tokenize/generate/decode/parse/normalize，不含模型加载和聊天模板渲染；本地 API 计时包括 HTTP 请求、服务推理与响应解析，不含服务启动。报告含平均、中位数、p95、各条时长、输入/输出 SHA256、样本数和 JSON 解析失败 ID；没有官方准确率或评分计算。新答复只指向参赛首页评审标准，未提供具体评分换算函数或短输入 complete 的新定义。

模型 JSON 解析失败时尝试恢复回复文本；非法情绪变 `""`、非法画像子数组变 `[]`、非法引用变 `[]`，随后继续。parse_failure_count 只计 JSON 提取失败，不涵盖所有字段非法。模型加载/生成/网络错误仍会终止进程，不能将其记录成输出格式已成功。缺权重时不能生成 mock 结果冒充正式运行。

## 已发现的包内问题

1. **样例 ID 与原始 schema 不一致，执行口径已澄清。** 三个输入 id 为 test1_000001_t5、test1_000001_t7、test1_000002_t5，原 schema 要求 `^test_[0-9]{6}_t[0-9]+$`，3/3 都不符合。参考代码原样回填 id，未执行完整 schema 校验。新答复明确原样回填；保留原始文件，团队有效 schema 删除旧前缀约束并另检 ID 对齐。旧快照仍不匹配，不冒称旧快照校验通过。
2. **3 条样例不足 100 条计时。** 默认运行该样例会按代码生成 complete=false，仍打印 PASS。该完整模型推理尚未实际完成；这里是静态逻辑结论。打印 PASS 不能代表 100 轮验收或平台得分。
3. **中途失败可能混合新旧产物。** submission 在开始推理前清空并逐行写，performance report 仅全部结束后覆盖。使用干净目录，检查退出码、样本数、complete 和摘要；不要凭文件存在判定成功。
4. **训练数据有语义异常。** 4 个预测点引用当前 user 之前的 assistant、5 个会话无预测点、202 组完整对话重复；JSON/schema 结构合法不代表标注顺序正确。见 [实际静态报告](../reports/integration/dataset-audit.json)，交由 A 在其数据处理区域隔离和记录。
5. **Transformers 依赖下限与导入符号不匹配。** requirements 写 `transformers>=4.40`，但 `run_inference.py:348–357` 在 Transformers 分支中无条件导入 `AutoModelForImageTextToText` 与 `MODEL_FOR_IMAGE_TEXT_TO_TEXT_MAPPING_NAMES`。官方 [v4.40.0 源码](https://github.com/huggingface/transformers/blob/v4.40.0/src/transformers/models/auto/modeling_auto.py) 没有这两个符号；[v4.50.0 源码](https://github.com/huggingface/transformers/blob/v4.50.0/src/transformers/models/auto/modeling_auto.py) 同时包含，且 [v4.50.0 包导出](https://github.com/huggingface/transformers/blob/v4.50.0/src/transformers/__init__.py) 包含该类。因此允许安装的 4.40.0 无法满足该原脚本导入；纯文本模型也不能绕过这些无条件导入。此结论来自版本源码比较，未实际安装这两版，不能据此声称 4.50.0 是首个兼容版本或已通过完整推理。后续候选环境需实际检查导入、模型兼容性并锁定精确版本；原始 requirements 不改。

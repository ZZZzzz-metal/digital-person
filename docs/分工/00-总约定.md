# B2 三人并行开发总约定（全 AI Agent 执行版）

> 选题：综合情感陪伴对话模型（数字人）。三个人已经组队，本计划只安排开发和交付。
> 执行方式：每人启动一个 AI Agent，分别运行 A、B、C 任务书。数据整理、编码、训练脚本、测试、文档、打包和提交准备交给 Agent；人只提供账号或权限、处理无法自动完成的登录，以及必要的最终确认。实际上传可由获得明确授权的 Agent 完成。
> 优先目标：先得到能聊天、能记忆、能离线推理、能按赛题格式提交的版本。界面和效果先做到可用，不做长时间打磨。
> 本文是新项目的内部开发合同。它不表示代码已经开发完成，也不表示训练、测评或报名提交已经完成。

## 1. 分工一览

| 代号 | 人的角色 | AI Agent 的责任 | 第一份交付 |
|---|---|---|---|
| **A** | 模型负责人 | 数据处理、离线模型推理、情绪理解、共情提示词、小规模训练、最小评测 | 假模型与真实模型使用同一输入输出格式 |
| **B** | 队长兼集成负责人（建议） | 共享合同、记忆融合、后端、官方接口适配、Docker、离线验收 | 可启动的后端与固定 API |
| **C** | 产品交付负责人 | 前端聊天、简易数字人、mock、演示、方案与商业测算材料 | 不依赖模型或后端的 mock 页面 |

实际队长若另有安排，只转移队伍账号、提交和进度协调；不要因此交换代码目录。A/B/C 先作为成员代号，队员姓名后补。

### 今天直接这样开始

1. 三人各用独立克隆或独立工作目录，分别创建 `codex/b2-a-model`、`codex/b2-b-server`、`codex/b2-c-web` 分支。
2. 三人分别克隆本仓库，使用独立工作目录。三个 Agent 都先读本文，再读自己的任务书。
3. A 立即运行 A0–A2；B 立即运行 B0–B2；C 立即运行 C0–C2。不要等别人把真实功能做完。
4. B 在当天前 2 小时交合同与可运行骨架；A、C 在此期间各自创建自己的文件，不让 B 提前生成再交接这些文件。
5. 把每份任务书最上面的“给 Agent 的启动指令”直接交给对应 Agent。Agent 按顺序持续执行，不需要人逐条分配。

## 5. 共享类型（B 维护 `src/b2_core/contracts.py`）

以下是内部 v0.1 合同。官方适配由 B 做字段映射，不能把它直接称为官方协议。JSON 字段统一 snake_case，ID 为字符串，时间为 UTC ISO 8601（`Z` 结尾），页面按北京时间展示。

```python
from typing import Literal
from pydantic import BaseModel, Field

Emotion = Literal['neutral', 'happy', 'sad', 'anxious', 'angry', 'unknown']
Expression = Literal['neutral', 'smile', 'concern', 'listening']

class Message(BaseModel):
    role: Literal['user', 'assistant']
    content: str

class MemoryItem(BaseModel):
    id: str
    key: str                     # 如 preferred_name、exam_subject
    value: str
    updated_at: str

class MemoryContext(BaseModel):
    prompt_text: str = ''
    retrieved_memories: list[MemoryItem] = Field(default_factory=list)

class CoreRequest(BaseModel):
    messages: list[Message]      # 最后一条必须是本轮 user；不得追加两次
    memory_context: str = ''
    persona: str = '伴学：中文日常陪伴助手'
    max_new_tokens: int = 256
    temperature: float = 0.3

class CoreReply(BaseModel):
    reply: str
    emotion: Emotion = 'unknown'
    expression: Expression = 'listening'
    model_version: str
    is_mock: bool = False

class ChatRequest(BaseModel):
    session_id: str
    client_turn_id: str          # C 每次发送生成一个；同次重试不换
    text: str

class ChatResponse(BaseModel):
    session_id: str
    client_turn_id: str
    reply: str
    emotion: Emotion
    expression: Expression
    retrieved_memories: list[MemoryItem]
    model_version: str
    elapsed_ms: int
    is_mock: bool

class SessionDTO(BaseModel):
    id: str
    title: str
    created_at: str
```

前端类型由 C 按 B 的 schema 生成或逐字段复制，以 schema 验证样例。`retrieved_memories` 表示本轮检索到的候选，不证明模型确实使用了每一项；界面名称用“本轮参考记忆”。情绪只是模型估计，用户界面不要呈现为心理诊断。

最小 JSON 样例：

```json
{
  "session_id": "session-demo-1",
  "client_turn_id": "turn-demo-1",
  "reply": "听起来你对这次考试有些担心。你愿意先说说最让你困扰的部分吗？",
  "emotion": "anxious",
  "expression": "concern",
  "retrieved_memories": [],
  "model_version": "baseline-v1",
  "elapsed_ms": 1200,
  "is_mock": false
}
```

这里的回复和耗时仅为协议样例，不是实测效果或性能。

## 6. 数据和记忆约定

B 建库，A 不直接写数据库，C 不直接读数据库。

| 表 | 必须字段 | 规则 |
|---|---|---|
| users | id, memory_enabled, created_at | 演示 API 首次访问分配随机匿名用户 cookie |
| sessions | id, user_id, title, created_at | 所有查询和删除都检查 cookie 用户归属 |
| messages | id, session_id, role, content, created_at | 成功推理后才原子写入本轮 user/assistant |
| memories | id, user_id, key, value, updated_at | `(user_id,key)` 唯一；用户确认的新值替换旧值 |
| turns | session_id, client_turn_id, response_json | 二者联合唯一；同次重试返回已完成结果 |

### 短期历史

最近 12 条已完成消息，最多约 4,000 中文字符；加当前用户输入后还须通过 A 的 tokenizer 检查模型上下文长度。超长时从最旧完整轮次开始移除，不截断当前问题。用户输入为空或超过 2,000 字符时 API 返回 400。

### 长期记忆

演示最小版只保存用户**主动确认**的事实：称呼、学习目标、偏好。内部 v0.1 key 白名单固定为 `preferred_name`（称呼）、`study_goal`（学习目标）、`exam_subject`（关注的考试科目）、`response_preference`（回应偏好）、`hobby`（兴趣）；前端使用选择项，不任意造 key。C 提供“保存为记忆”和修改/删除按钮，B 提供 CRUD；A 可以提出候选但不能绕过用户确认直接持久化。不得把情绪推断和健康诊断当作事实记忆。

记忆检索先按字段关键词与当前话题匹配，最多 5 项；不相关记忆不塞进 prompt。数据按 user_id 隔离，跨会话可复用，同名 key 更新值即可完成纠正。记忆关闭时不读取、不保存；关闭不等于删除，界面另有“清空记忆”。

**官方自动测评中的记忆**：以官方显式提供的历史/记忆字段为边界。没有用户标识与跨轮机制时，每个独立样本新建 `InMemoryStore`，不能复用演示数据库或把前一个样本记忆带给下一个。官方提供明确会话边界时才按其规则维护状态。

## 7. 模块接口（A、B 不互相等真实服务）

```python
# A：src/b2_core/model.py
class ModelEngine:
    def __init__(self, config_path: str): ...
    def generate(self, request: CoreRequest) -> CoreReply: ...

class MockEngine:
    def generate(self, request: CoreRequest) -> CoreReply: ...

# B：src/b2_core/memory.py
def build_memory_context(
    user_text: str, memories: list[MemoryItem]
) -> MemoryContext: ...

# B：src/b2_core/turn.py
def run_turn(
    request: CoreRequest, engine: ModelEngine | MockEngine
) -> CoreReply: ...
```

`run_turn` 是纯编排函数，校验输入输出并调用 engine，不依赖 HTTP/cookie/SQLite。B 的 HTTP 路由先取历史和记忆、构造 CoreRequest，再调用它；官方适配器直接根据官方输入构造 CoreRequest，再调用它。两种入口共用真实模型逻辑。

A0 的 MockEngine 当天交付；B 在 MockEngine 尚未出现时可在自己的测试目录使用 stub，不修改 A 文件。模型加载在进程启动后只做一次，不能每条消息重新加载。

情绪到表情的默认映射：happy → smile；sad/anxious → concern；angry → listening；neutral/unknown → neutral。A 输出不合法的情绪时归 unknown，表情归 neutral；真实推理失败时抛出可识别错误，B API 返回 503，不把固定文案伪装成真实结果。

## 8. 演示 HTTP API（C 只依赖这些）

所有成功响应直接返回表中的 JSON；错误统一 `{ "error": { "code": "MODEL_UNAVAILABLE", "message": "模型暂不可用" } }`。400 参数错误、404 资源不存在或不属当前用户、409 当前会话有请求在执行、503 模型不可用。`GET /health` 是例外：即使 degraded 仍返回 200 和健康状态。

| 方法与路径 | 请求 | 响应 |
|---|---|---|
| `GET /health` | 无 | `{status:'ok'\|'degraded', model_ready:boolean, is_mock:boolean, model_version:string}` |
| `POST /api/sessions` | `{title?:string}` | SessionDTO |
| `GET /api/sessions` | 无 | SessionDTO[]，仅当前用户 |
| `GET /api/sessions/:id/messages` | 无 | Message[]，按插入顺序 |
| `POST /api/chat` | ChatRequest | ChatResponse；非流式，前端展示等待状态 |
| `DELETE /api/sessions/:id` | 无 | `{ok:true}`；仅删该会话、消息和 turns，长期记忆保留 |
| `GET /api/memories` | 无 | `{enabled:boolean,items:MemoryItem[]}` |
| `PUT /api/memories/settings` | `{enabled:boolean}` | `{enabled:boolean,items:MemoryItem[]}` |
| `PUT /api/memories/:key` | `{value:string}` | MemoryItem；由用户明确点击保存或修改 |
| `DELETE /api/memories/:id` | 无 | `{ok:true}` |
| `DELETE /api/memories` | 无 | `{ok:true}`；清空当前用户全部长期记忆 |

本机演示不做完整账号系统。cookie 用户标识由 B 分配，C 不传任意 user_id；两个浏览器或两个独立 cookie 的记忆必须隔离。开发跨域通过 Vite 的 `/api`、`/health` 代理处理。

Mock 模式：A 的 engine 返回 `is_mock=true`，C 本地 mock 同样返回 true，并显示“演示数据”。真实模式不允许自动悄悄退回 mock。

## 10. 全 AI 并行流程

1. 三个 Agent 使用独立分支/独立工作目录，避免同一份 Git 工作区切来切去。Agent 不在共享目录同时安装依赖、改锁文件或创建提交。
2. B 先提交 contracts 和自身骨架；A、C 同时在各自目录开工。拉取共同骨架后，各自继续，不等待对方完成 P1。
3. 每完成一个可运行任务就提交。提交说明写“完成什么、运行了什么检查、还有什么阻塞”。B 每晚统一集成一次；合并冲突由文件主人修，其他任务继续。
4. 共享接口变更：提出问题 → B 改合同与 schema → A/C 同步 → 再改实现。不得先改代码再要求别人猜。
5. Agent 默认自主解决可逆的实现选择；缺账号、缺官方文件、确有权限阻塞时才列出需要人的具体操作。禁止编造测评通过、训练收益、商业数据和提交成功。

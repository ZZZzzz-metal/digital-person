### B1. 共享合同与可运行骨架（当天前 2 小时交付）

**输入**：总约定第 4–8 节。

**输出**：contracts、共享 Pydantic 类型、可启动 FastAPI、健康接口、Python 环境声明。

- `src/b2_core/contracts.py` 使用总约定类型，生成 JSON Schema 和至少一组 CoreRequest、CoreReply、ChatResponse 示例。
- `__init__.py` 不导入或加载大模型，保证 A 尚未交实现时也能运行接口测试。
- 演示后端以测试 stub 注入 engine，`GET /health` 表明 `is_mock=true`。真实模式配置不能自动降成 mock。
- 只创建 B 负责的文件，不提前生成 A 的 `model.py` 和 C 的 `apps/web/`。
- README 写后端启动、mock/real 模式切换、前端代理目标。默认绑定 `127.0.0.1:8000`。
- `.gitignore` 排除真实 cookie/数据库、权重、大数据、密钥和生成镜像。

**最小验证**：新环境按 README 安装后可启动，health 返回 JSON；schema 校验样例通过。把这一份骨架提交，供 A/C 同步，继续开发。

### B2. 数据存储、匿名用户和会话接口

**时间**：10/09–10/10。

**输入**：总约定第 6、8 节。

**输出**：SQLiteStore、InMemoryStore、sessions/messages/turns 等表与对应 API。

- 匿名 cookie 第一次创建随机 user_id，不接受前端传任意 user_id。所有会话和记忆操作验证归属。
- 会话创建、列表、历史和删除按固定接口返回；列表和历史不能混入其他用户数据。
- 同会话一次只处理一轮；推理异常时不提交半个对话。成功时 user、assistant、turns 在一个事务中写入。
- `(session_id,client_turn_id)` 去重；已成功的重复请求直接返回原 response。两条相同文本但不同 turn_id 是两次真正发送，不能按文字去重。
- 并发执行未完成时返回 409，前端保留原输入和 turn_id 后重试。

**最小验证**：两组 cookie 创建独立会话，互相访问返回 404；同个 turn_id 重试只多一对消息；模拟模型失败不留下 assistant 假回复。

### B3. 记忆保存、检索、纠正和关闭

**时间**：10/10。

**输入**：用户明确点击保存的 key/value，当前话题与已保存记忆。

**输出**：memory CRUD、`build_memory_context(user_text,memories)`、记忆候选列表。

- key 只允许约定的称呼、学习目标、偏好等事实字段；值限制长度并做基础输入校验。
- 同一用户同一 key 采用更新，不把矛盾旧值一起塞入 prompt。
- 最多检索 5 条相关事实，生成简短说明；记忆作为用户数据，不能当作覆盖系统约束的指令。
- 关闭时不读、不写；清空只删当前用户。删除某会话不自动删除其长期记忆。
- 不从情绪估计推导诊断或主动存入隐私事实。自动候选若未确认，不能落库。

**最小验证**：高数→用户确认改为线代→下一轮只用线代；关闭记忆后 CoreRequest.memory_context 为空；另一个 cookie 看不到旧值。

### B4. 聊天编排与真实模型接入

**时间**：10/10–10/11。

**输入**：ChatRequest、历史、记忆、A 的 engine。

**输出**：ChatResponse；纯 `run_turn` 可被演示与官方适配共同调用。

- 获取最近 12 条已完成历史，移除最旧完整轮次，最后追加当前用户输入一次。
- 构造 CoreRequest，先传相关 memory_context，再由 A 保证 tokenizer 长度不超上限。
- `run_turn` 只验证并调用 engine；不在这里启动 HTTP、访问浏览器或要求 cookie。
- 模型在进程内只初始化一次；给演示请求设置合理超时。失败返 503，并保留用户可重试状态。
- 返回 `retrieved_memories` 的名称含义是候选记忆，不说成模型必然引用的事实。
- 模型输出/表情异常按合同归一化，记录具体模型版本、实际 elapsed_ms 与 is_mock。

**最小验证**：用真实模型发 6 轮对话；历史不重复，记忆按规则加入，异常不变成“假成功”。与 C 做一次“发消息→保存记忆→新会话→纠正”联调即可，不反复润色文案。

### B5. 官方离线适配器（提交工作的核心）

**时间**：10/12–10/14；B0 官方协议清楚后开始依赖部分。

**输入**：实际官方样例、官方输出协议、A 的本地模型。

**输出**：官方允许区域内的适配器和入口、输出格式检查。

- 官方输入映射为 CoreRequest，官方历史里的当前 user 只保留一次；不额外注入 demo 剧本或测试参考答案。
- 返回映射为实际官方输出，不新增未允许字段，不把内部 ChatResponse 整包写过去。
- 每个独立样本重新建立 InMemoryStore；只有官方明确同一会话的字段才允许跨轮保持记忆。
- 不读取演示库，不打开 Web，不启动 HTTP 服务，不调用在线模型接口。
- 只写指定结果目录，保持样本 ID 对齐；失败退出并留日志，不能用空白或固定回复伪装合格预测。
- 兼容规则、输出长度和批处理方式都以实际 B2 协议为准。

**最小验证**：官方样例全部能产出格式正确结果；两份独立样本顺序交换后，不出现前一个用户记忆污染后一个。缺输入/权重时给清楚错误日志。

### B6. 基础镜像与禁网自测

**时间**：10/14–10/16。

**输入**：官方基础镜像、依赖锁定、完整模型包和官方适配器。

**输出**：可提交镜像、权重/依赖清单、`reports/integration/离线验收.md`。

构建阶段准备依赖，运行阶段禁网。模型本体、tokenizer、配置、适配器权重及必要依赖全部在镜像内；只带 LoRA 文件而缺基础模型不算完整。

在实际 GPU 环境执行一次无网络自动运行：加载指定输入、生成指定输出、校验格式、记录运行时长、错误和版本。预热与完整输入限制照官方说明；若有 CPU 演示只能单独标记，不能称 GPU 官方验收已通过。

把本地缓存路径改成容器实际路径，但不改 A 模型语义配置；有问题交 A 修复。检查启动不要求浏览器、人工输入、运行时下载或外部密钥。

**完成标准**：禁网容器实际成功运行，日志对应同一镜像摘要与模型版本。没权限构建或没 GPU 时，写清尚缺的动作，保留准备好的脚本，不写“已通过”。

**输出**：`docs/提交记录.md`、真实平台状态截图、一个可回退镜像。
